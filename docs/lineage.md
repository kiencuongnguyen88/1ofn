# Method Lineage

`1ofN` is an independent public method.

## Failure / need → invention

The method did not start as a naming exercise. It came from a recurring failure:

> Several options can all be reasonable; analysing each option in isolation can make every option look stronger while still failing to reveal what should actually survive.

Inside DIAMOND OS, an internal ancestor named **BBR** evolved to address this failure.

BBR gradually combined several behaviours:

1. expand evidence and the option space before narrowing;
2. search for missing or hybrid candidates rather than score only the options already supplied;
3. challenge contrary evidence and hidden assumptions;
4. use a removal test to determine whether a candidate has distinct material value;
5. allow KEEP / MERGE / PARK / REMOVE / BLOCKED;
6. audit the provisional result before commitment.

The internal ancestor eventually gained stage contracts, provenance rules, contradiction checks, verdict rules, and stop conditions.

## Why 1ofN is not an export of BBR

The public method was **recompiled**, not copied out of an internal runtime.

`1ofN` does not require:

- DIAMOND OS;
- DRC terminology;
- source/runtime governance;
- internal role maps;
- databases;
- repository infrastructure;
- the acronym BBR.

What survives is the **force**:

- expand before narrowing;
- challenge attractive options;
- never let candidates disappear silently;
- test counterfactual loss;
- preserve MERGE and PARK as real outcomes;
- expose uncertainty;
- stop when further analysis no longer changes the decision.

## Naming evolution

A long-form English public name was tried first and rejected because it was difficult to remember for the initial Vietnamese audience.

Naming then shifted to a **token-first** approach.

Human selected `1ofN` because:

- the meaning is remembered after one explanation;
- it directly encodes “one among N options”;
- it is easy to type and visually distinctive;
- it can be used naturally in a sentence such as “run 1ofN on this case”;
- it does not require a long-form expansion.

The public name therefore does not try to describe all of the machinery. It names the **situation that calls for the method**.
