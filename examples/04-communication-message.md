# Worked Case 4 — Choose One Primary Message for a Public Launch

## Situation

A creator is preparing the first public-facing explanation of a decision method.

Several messages are true:

1. the method uses five stages;
2. material runs use a full-baseline guard;
3. it reduces plausible alternatives without silently losing material value;
4. its execution tools can be replaced;
5. it has evaluation and follow-up surfaces.

Desired outcome: a reader unfamiliar with the method should remember **one reason to care**, while the deeper method remains accurate underneath.

Constraints:

- the primary message must be true;
- secondary points may support the lead, but should not compete with it;
- the message must not imply that every run forces exactly one winner;
- no popularity, performance, or calibration claim may be invented.

## 1. FRAME

The real decision is not “Which facts about the method are true?”

It is:

> Which primary message should lead the public surface so a new reader understands why 1ofN exists, while the rest of the method remains available as proof and depth?

## 2. EXPAND

Add two candidates:

6. **why-now pain** — generative AI makes it cheap to produce more plausible options, so the bottleneck moves downstream to deciding what deserves commitment;
7. **pain + method route** — lead with the option-overload pain, state the core 1ofN promise accurately, then use stages, guards, and evals as supporting proof rather than co-headlines.

### FULL_BASELINE

Candidate 7 is the explicit `FULL_BASELINE` for this communication decision.

It preserves:

- the reader-facing pain;
- the method's actual purpose;
- the guard against a forced single-winner interpretation;
- room for technical proof underneath;
- future flexibility to change tools without changing the public method.

It is complete enough for this launch surface without trying to explain the whole repository in the headline.

## 3. CHALLENGE

| Candidate | Support | Contrary evidence / failure mode |
|---|---|---|
| Five stages | concrete and inspectable | implementation-first; a new reader may not yet know why the stages matter |
| Full-baseline guard | strong differentiator for material decisions | too technical for the first contact surface |
| Reduce without losing material value | accurate core promise | abstract unless connected to a recognizable pain |
| Replaceable tools | future-proof architecture | weak reason for a first-time reader to care |
| Evaluation / follow-up | good proof discipline | proof is not the same thing as the primary problem |
| Why-now pain | immediately recognizable in an AI-heavy environment | can become a generic "too many options" slogan if detached from the method |
| Pain + method route / FULL_BASELINE | links the pain to the actual method and leaves technical depth underneath | needs disciplined copy so supporting details do not become competing headlines |

## 4. DISTILL

- Five stages → **MERGE** into supporting proof.
- Full-baseline guard → **MERGE** into deeper technical proof.
- Reduce without losing material value → **MERGE** into the lead explanation.
- Replaceable tools → **PARK** for architecture-focused communication.
- Evaluation / follow-up → **MERGE** into credibility/proof.
- Why-now pain → **MERGE** into the selected route.
- Pain + method route / FULL_BASELINE → **KEEP**.

No candidate disappears silently.

## 5. DECIDE

**Selected path:** lead with the downstream decision pain, then immediately connect it to the method.

A compact public surface can be:

> Generative AI made producing plausible options cheap. The hard part is deciding what deserves to survive.

Then define 1ofN accurately:

> 1ofN helps reduce several plausible alternatives without silently losing material value.

The five stages, full-baseline guard, verdicts, removal test, and evals remain underneath as evidence and depth rather than competing first-screen messages.

### Why it survives

- it gives a new reader a reason to care before explaining machinery;
- it preserves the actual 1ofN problem rather than turning the project into a generic AI ranking tool;
- it does not require every run to produce exactly one winner;
- it lets the repository dogfood its own method: one public surface has one primary message, while deeper value remains available below it.

### Reversal condition

If outside readers repeatedly interpret “what deserves to survive” as “always choose exactly one winner,” move the existing guard closer to the hero message or return to the simpler first-contact line:

> When several options all make sense.

### Next action

Use one primary message on the next public 1ofN surface and collect external evidence about what readers actually remember or misunderstand.
